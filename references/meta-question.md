# 元问题方法论：每份公文都在回答一个问题

> 最重要、最艰难的工作，从来不是找到正确的答案，而是提出正确的问题。——彼得·德鲁克

## 一、公文写作的出发点：锁定"元问题"

接到写作任务，第一反应不该是"格式怎么摆""第一段怎么开"，而是：**读到这份文件的人，脑子里装着什么疑问？**

| 文种 | 读者问的元问题 | 答案方向 |
|------|--------------|---------|
| 通知 | 我接下来要干什么？ | 任务、时限、要求、联系人 |
| 请示 | 我为什么要批准？ | 必要、合规、可行、成本可控 |
| 汇报 | 事情办到什么程度了？ | 进度、成效、问题、下一步 |
| 方案 | 凭什么照你说的来？ | 阶段划分、任务清单、责任人、时间表 |
| 纪要 | 最终定了哪几条？ | 决议事项、责任分工、完成时限 |
| 调研报告 | 现状如何、怎么破？ | 问题梳理、根源分析、对策建议 |
| 经验材料 | 凭什么干得好？ | 关键环节、可复制做法、核心规律 |
| 整改报告 | 改了没有、改到什么程度？ | 已完成项、推进中项、长效机制的建立进度 |

每一种文种对应一道不同的考题，我们写的每一份公文就是在交一份答卷。

**核心操作**：接到任务后，在草稿纸上写一句话——"读者看完这份文件后，应该获得哪个问题的明确回答？"然后用一句话把答案概括出来。这句话就是整篇稿子的锚点，后面的结构和材料都围着它转。

## 二、公文被退回的根源：答非所问

绝大多数被退回的稿子，表面看是结构问题、详略问题，底层原因只有一个：**写的人没有事先锁定"这份文件要回答的核心问题是什么"。**

### 三种典型的"答非所问"

| 场景 | 读者真正要的 | 实际交出去的 |
|------|------------|------------|
| 写请示 | "我为什么要同意？" | 三页背景铺陈+末尾一句"妥否，请批示"，主次倒置 |
| 写方案 | "谁来干？干什么？什么时候交账？" | 指导思想+基本原则+总体目标占大头，没看到能拍板的东西 |
| 写总结 | "到底推动了什么？数据变化多少？解决了哪个堵点？" | 通篇"高度重视""精心组织""取得显著成效" |

就像考试时题目问"请分析原因"，交上去的是"事情经过"的流水账——答得再工整也拿不到分。

## 三、从元问题推导结构：三步拆解法

锁定元问题之后，不需要冥思苦想"第一段写什么"，答案本身就在指引框架走向。

### 第一步：把元问题拆成三到五个子问题

以**请示**为例，元问题是"领导为什么要批准"，往下拆：

1. 这事有没有必要做？（必要性）
2. 有没有政策依据？（合规性）
3. 打算具体怎么操作？（可行性）
4. 要投入多少资源？（成本）
5. 有没有风险？怎么兜底？（风险兜底）

### 第二步：按读者的认知顺序排列

领导审批时的思维路径是"**先判断该不该做 → 再看怎么做 → 最后衡量代价**"。所以子问题的呈现顺序应该是：必要性 → 合规性 → 可行性 → 成本 → 风险兜底。这就是请示的经典结构——不是机械套模板套出来的，而是从读者的思维链条推导出来的。

同一个模板，有人写得让领导一遍过就签字，有人写得让领导翻来覆去总觉得差点什么，区别就在推导过程是否真正站到了读者那边。

### 第三步：每个子问题对应一个段落或板块，写完自查有没有漏答

每写完一个板块，回头看：**这部分在回答哪个子问题？**

- 如果某一段回答不了任何子问题 → 大概率可以砍掉
- 如果某个子问题在全文中找不到对应段落 → 说明有漏洞需要补

这样永远不会写出"不知道为什么要有这一段"的内容。每段存在的理由都很明确：它在回答读者脑子里的某个具体疑问。

## 四、高手多做一步：预判追问

合格的笔杆子能把元问题回答完整。追求"一稿过"，还需要往前多走一步：**预判读者看完之后可能冒出的追问。**

我们不仅要回答领导明面上的问题，还要把他心里没说出口但一定会想到的疑虑提前化解掉。

### 举例：一份购买办公设备的请示

必要性、合规性、方案都写了，但领导心里可能还会冒出：

- "去年不是刚换过一批吗？为什么又要买？"
- "其他同级单位是什么配置标准？"
- "如果今年预算收紧，能不能分批走？"

这些追问不会出现在正式批复里，但它们实打实影响着领导签字的速度。在正文中顺带一两句话交代清楚：

> "本次申请设备与去年更换的类别不同，属于XX范畴"
> "经了解，同级单位配置标准为XX"
> "如需分步实施，可按XX节奏推进"

领导看完一遍就能形成判断，不需要再打电话找你问半天。

### 预判追问的三个来源

1. **角色代入**：假设我们就是签字的那个人——批了这事万一出问题，别人会怎么问我们？
2. **历史复盘**：上次类似的文件，领导在审批环节问了什么、批注了什么？这些就是最真实的追问题库。
3. **反对者视角**：如果有人想否掉这件事，会拿什么理由来反对？你在文中提前回应，等于给领导批准这件事提供了挡箭牌。

## 五、元问题自检清单

写完稿子，拿五条逐项过一遍：

- [ ] **元问题清不清楚？** 能不能用一句话说出"这篇稿子在回答什么"？连自己都说不出来，读者就更感受不到
- [ ] **子问题拆没拆？** 拆了，结构天然有逻辑；没拆，大概率是想到哪写到哪的散装状态
- [ ] **每一段是否对应某个子问题？** 找不到归属的段落，十有八九是凑字数的
- [ ] **有没有预埋追问的回应？** 完全没有预判的文件，容易"乍一看完整，细想总差点什么"
- [ ] **有没有不回答任何问题的纯套话？** "高度重视""精心组织""全面加强"本身没有信息量，如果后面没跟具体事实或数据，果断删

## 六、本质

公文写作的真正门槛不在文字功夫，而在思维品质：

- 你能不能快速抓住问题要害
- 你能不能把复杂议题拆成有逻辑的几个层面
- 你能不能跳出自己的视角站到读者那边去想

思路清晰的人，哪怕语言朴素，写出来的东西也比辞藻华丽但逻辑混乱的强太多。**下次接到任务，别急着开文档。先问自己一句：这份文件，到底要回答什么？** 想清楚再动笔。这一步，就是写作中最值钱的一步。
