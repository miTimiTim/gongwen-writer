# 问题链提纲法：跳出模板化误区

> 你搭的是标题框架，不是解题逻辑。好提纲的底子是清晰的工作判断，不是精巧的文字游戏。

## 一、模板为什么害了你

传统提纲的套路大家都知道：翻范文 → 凑标题 → 硬拼"提高认识—强化举措—加强保障"的三段式。看着像模像样，写出来却千人一面，领导看了觉得"哪儿都对，哪儿都没用"。

### 两种提纲对比

同样写基层减负专项工作讲话稿：

**传统模板提纲：**
```
一、提高站位，充分认识基层减负的重要意义
二、聚焦重点，扎实推进基层减负各项任务
三、强化保障，确保基层减负工作落地见效
```

**问题链提纲：**
```
一、减负年年抓，为什么还会反弹回潮？
二、今年减负，要实打实解决哪几件事？
三、怎么确保减下去的负担不反弹？
```

前者在凑结构，后者在解问题。哪个能帮你把稿子写深写透，一目了然。

提纲的本质不是"标题集合"，是**"解决问题的思路闭环"**。真正立得住的提纲，是顺着文稿要解决的核心问题一层一层拆下去，形成一条自洽的逻辑链——每个板块都在回答问题，所有内容都指向行文目标。

## 二、三步法：问题链搭建

### 第一步：锚定根问题——把模糊目的变成具体命题

所有公文都有行文目的，但多数人对目的的理解止步于"总结工作""部署任务""汇报情况"。目的停在这个层面，提纲必然滑向模板。只有把目的落实为一个**具体的、待解决的真问题**，才算找到了提纲的"根"。

**用三个问题锁定根问题：**

1. **受众看完这篇稿子，需要扭转什么认知？**（思想层面的堵点）
2. **稿子落地之后，要推动哪些看得见的动作？**（执行层面的卡点）
3. **往长远看，要啃掉哪块硬骨头？**（业务层面的痛点）

三个问题未必都有答案，但至少能帮你把空泛的"目的"锁定到实处。

**根问题决定提纲方向（以"优化营商环境讲话稿"为例）：**

| 真实症结 | 根问题 | 提纲方向 |
|---------|--------|---------|
| 部门审批互为前置、企业办事来回跑 | 怎么打破壁垒、让企业只跑一次？ | 破壁垒 → 减环节 → 优流程 |
| 惠企政策兑现慢、企业感知弱 | 怎么让政策找企业，不让企业找政策？ | 免申即享 → 直达快享 → 闭环督办 |
| 只说"欢迎来投资"但项目落地推不动 | 怎么从"口头欢迎"变成"全程服务"？ | 一个项目一个专班 → 全流程陪跑 → 问题不过夜 |

根问题一偏，后面标题再漂亮也是白搭。

### 第二步：搭建问题链——让逻辑闭环替代标题堆砌

根问题找准了，先别急着凑小标题。第一件事是把核心问题拆成层层递进的子问题，形成"**根问题 → 子问题 → 落地项**"的完整链条。每一级标题的实质是对应问题的解法；整篇提纲连起来，就是一套完整的解题路径。

**两种常见搭法：**

#### 递进式：顺着认知规律往下走

沿"为什么—是什么—怎么办—怎么保"的路径展开，符合多数人的阅读习惯。以基层减负讲话为例：

```
根问题：为什么减负年年抓，仍反弹回潮？
├── 现状诊断：当前形式主义冒出了哪些新变种？
│   └── 反弹背后，权责不对等的堵点卡在哪？
├── 核心命题：今年减负要精准解决哪几件事？
│   ├── 哪些报表、会议、考核必须刚性砍掉？
│   └── 哪些事权、资源必须实打实沉下去？
└── 保障闭环：怎么确保减下来的不反弹？
    ├── 谁来盯、怎么监测？
    └── 反弹了怎么追责、标准是什么？
```

这样搭出来的提纲，每一部分都在答题，不存在"正确但无用"的套话，动笔时自然有话可写。

#### 并列式：多条线并行攻坚

适合综合性强、多线任务并进的文稿。各子问题是独立的攻坚方向，合在一起指向同一个根问题。

以数字政府建设方案为例，根问题是"怎么实现政务服务一网通办、全域可办"：

```
├── 数据共享的壁垒怎么打通？
├── 办事流程怎么从根上再造？
├── 基层服务终端怎么铺到位？
└── 数据安全的底线怎么守住？
```

四条线各管各的，却共同托住一个目标。**搭建时注意**：各板块之间内容不重叠、合起来不遗漏。

### 第三步：校准颗粒度——粗细拿捏看对象、看场景

提纲太粗，写到一半频繁卡壳；太细，反而把思路框死了。临界点看两头：

| 维度 | 粗 | 细 |
|------|---|----|
| **受众** | 给主要领导过目：粗一点，留出核心观点、关键数据和整体走向，领导要看方向判断不是细节罗列 | 给起草组内部协作：素材出处、案例选用、表述口径全标清楚，省得来回对齐耗时间 |
| **场景** | 现场宣读的讲话稿：节奏感重要，哪里停顿加重、哪里一笔带过心里有数 | 正式印发的文件：精确到条款项，权责边界、执行标准不能有含混空间 |

## 三、删减原则：凡是不回应根问题的，砍掉不犹豫

很多提纲越写越臃肿，就是舍不得丢"漂亮的废话"，结果主线被稀释得面目模糊。

### 提纲搭完后做一轮反向校验再动笔

1. **删**：逐条过，把不扣题的"正确废话"拿掉
2. **并**：看并列板块之间有没有内容交叉，有就合并
3. **补**：顺着问题链从头捋一遍，哪个环节论证断了、逻辑跳了，及时补上

这一轮做下来，留在提纲里的每一条都有它存在的理由。动笔时不会写着写着跑偏，审稿时也经得住追问。

## 四、与现有框架体系的关系

问题链提纲法不否定传统的"三段式""总分总"等框架（见 `writing-frameworks.md`），而是提供一个**前置思考步骤**：在选定具体框架形态之前，先用问题链锁定"这篇稿子到底要解决什么"。根问题找准了，三段式还是总分总，自然知道该用哪个。

**操作顺序**：
1. 先用本文的方法 → 锚定根问题 + 搭建问题链
2. 再用 `writing-frameworks.md` → 选择具体框架形态（块状/条状/三段式等）
3. 最后用 `master-techniques.md` → 打磨标题措辞

## 五、速记公式

> 别上来就凑对仗、套三段。先在纸上写下这篇稿子要解决的三个真问题，思路顺着问题走，框架跟着逻辑长，写出来的东西自然不一样。
